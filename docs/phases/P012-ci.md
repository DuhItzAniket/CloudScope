# P012 — CI

Status: DONE     Date: 2026-10-04     Commit: (this commit; workflow first pushed in a0e6af2)

## Objective
Build and test every supported platform automatically on each push, enforce the licence policy, and make CI failures readable from the development machine.

## Requirements covered
NFR-MNT-02 (CI on Windows x64, Linux x64, Linux arm64), FR-PLT-01 (platform evidence), ADR-010 consequence (automated licence gate), NFR-SEC-02 (partly: see Deviations).

## Design notes
- Workflow `.github/workflows/ci.yml`, five jobs: **Debian 13 x64**, **Debian 13 arm64** (GitHub's arm64 runner: real hardware of the Raspberry Pi's architecture), **Ubuntu 26.04 x64** (newest Qt and GCC), **Windows x64** (MSVC 2022, vcpkg, Qt 6.8.3 installed with aqtinstall: the oldest supported Qt, whereas the laptop has 6.9.3), **Python tools**.
- Each C++ job: configure with warnings as errors, build and test Debug and Release, licence check, upload Release binaries and `THIRD_PARTY_LICENCES.md` (14 days).
- Linux jobs run in the distribution's container and install dependencies with the same script as a developer or a Pi (`tools/build/install-deps-debian.sh`).
- Windows caches: the Qt installation, and vcpkg's compiled packages. The vcpkg cache is saved only when its content changed, and also when a later step fails, so a compile error in CloudScope does not throw away 18 minutes of dependency builds.
- **Readable failures without signing in** (`tools/ci/run.py`, `tools/ci/status.py`): full job logs need a GitHub sign-in, annotations do not. Every step runs through `run.py`, which on failure attaches the error lines and the end of the output to the commit as annotations; `status.py` reads job results and annotations through the public API (with ETag requests, so polling does not use up the rate limit).
- **Licence gate** (`tools/ci/licence_check.py`, table `packaging/licences/third_party.toml`): see `docs/dev/ci.md`. ADR-010 is amended with the exact allow-list and the "system library" class.
- Only GitHub's own actions are used (`checkout@v7`, `cache@v6`, `upload-artifact@v7`, `setup-python@v7`); the workflow has read-only permissions and no secrets.
- Branches named `ci/...` also trigger the workflow, for trying workflow changes without touching `master`.

## Safety & failure-mode notes
- **A cache can hide a broken dependency build.** The vcpkg cache key follows the cache content, not `vcpkg.json`; vcpkg itself decides per package (by ABI hash) whether a cached binary is still valid, so a compiler or port update rebuilds what it must.
- **Annotations are limited** (10 per step, a few kilobytes each): `run.py` keeps the error lines and the last 400 lines. A failure whose cause scrolled out of that window needs the full log on GitHub.
- **The Linux licence gate covers direct dependencies only.** Distribution packages bring their own dependencies (Debian's OpenCV links many libraries); CloudScope's packages will depend on them, not ship them. If CloudScope ever bundles Linux libraries (AppImage, Flatpak), the gate must be widened to the full closure.
- The emulated arm64 build of P011 and the real arm64 runner give the same result (14/14 tests); a Raspberry Pi 5 itself has not built the code yet. That remains to be done when the Pi is set up (D3: laptop host for now).
